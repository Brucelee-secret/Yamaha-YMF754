# Yamaha YMF754 (DS-1E) for Mac OS X 10.6.8

Здесь находится экспериментальный kernel extension для карты Yamaha DS-1E / YMF754
и PCI-идентификатора `vendor 0x1073`, `device 0x0012`
(`IOPCIPrimaryMatch = 0x00121073`).

Целевая среда: Intel Mac, Mac OS X 10.6.8, Xcode 4.2, SDK 10.6 и LLVM GCC 4.2.
Проект создан в формате Xcode 3.2/4.x, чтобы его можно было открыть в Xcode 4.2.

## Текущее состояние

Это экспериментальный драйвер. На целевой карте владелец подтвердил чистое
аналоговое воспроизведение, микрофон, громкость, mute и 3D Wide с device-workloop
IRQ-схемой. В этой версии снова регистрируется отдельный S/PDIF PCM-выход;
физический цифровой сигнал и переключение выходов в этой конкретной сборке
нужно проверить повторно.
Сохраняются PCI match/проверка ID, BAR0, reset,
таймауты и встроенная firmware. Добавлены:

- Два отдельных выхода `IOAudioEngine`: аналоговый и S/PDIF PCM,
  **48000 Гц, signed 16-bit LE, стерео**.
  Преобразование других частот выполняет CoreAudio; специальный 44,1-кГц тракт
  YMF754 пока не используется.
- Два голоса ALSA с двумя банками каждый; размеры банков читаются из firmware.
  Таблицы всех 64 голосов, capture/effect banks и work area выделяются полностью.
  Capture-bank и DMA-кольцо микрофона публикуются до запуска DSP, так как
  прошивка фиксирует MAPOFREC при старте MODE. DSP работает только пока активен
  аналоговый выход или входной клиент; данные передаются приложению только
  активному входному потоку. Если входной клиент активен без выходного,
  аналоговый DAC автоматически заглушается; появление клиента воспроизведения
  восстанавливает его. Обработка effect-bank пока не используется.
  Кольцо PCM: 16384 кадра / 65536 байт.
- Непрерывные DMA-области ниже 4 ГиБ и проверенные 32-битные **bus addresses**
  через `IODMACommand`, а не преобразование указателя CPU в адрес устройства.
- Фильтры shared PCI IRQ находятся на workloop устройства. В простое активен
  аналоговый источник для служебных IRQ; при выборе SPDIF он отключается, и
  включается цифровой. DSP и DMA запускает только один выход за раз; при
  переключении предыдущий аудиодвижок останавливается. Позиция DSP читается по
  IRQ, `takeTimeStamp` вызывается при обороте кольца.
- AC'97: master volume управляется стандартным `IOAudioLevelControl` — ползунок
  macOS меняет аппаратный AC'97 Master Volume; PCM остаётся unity, analog
  monitoring выключен. Начальный уровень — 16/31 (−22.5 dB), 0 — mute, максимум —
  0 dB. При отсутствии выходного клиента native DAC заглушён независимо от
  сохранённого положения регулятора. EAPD/неизвестные настройки платы не переключаются.
- Преобразование Float32 mix buffer в S16 целочисленной обработкой IEEE-754:
  код драйвера не использует FPU/SSE, NaN заглушается, переполнение ограничивается.
- Микрофонный вход захватывается через native ADC; отдельная чувствительность
  управляет AC'97 Mic Volume. Аналоговый мониторинг микрофона заглушён.
- Mute — отдельный AC'97 переключатель; при снятии mute восстанавливается выбранная
  громкость.
- Аналоговый и цифровой выходы используют общий DSP и DMA-контроллер, поэтому
  активен только выбранный выход. Запуск SPDIF останавливает аналоговый поток и
  микрофон; микрофонная запись при активном SPDIF не поддерживается. Для SPDIF
  задаётся обычный стерео PCM, без raw AC-3 passthrough.
- В качестве базы взята однодвижковая схема из приложенного mic-ok ZIP, а не
  распакован проект целиком: в архиве массивы firmware подключаются через
  скрытый `DERIVED_FILE_DIR/YMFPCIFirmwareData.inc`, тогда как текущая сборка
  хранит firmware явно в `Driver/YMFPCIFirmware.cpp`. Проверенную схему загрузки
  firmware и работающий микрофонный путь сохранены.
- При запуске аналогового кодека SigmaTel STAC9708 включается экспериментальный
  эффект по последовательности из присланного рабочего исходника: `AC'97 3D
  Control` (`0x22`) получает `0x0f0f`, а `General Purpose` (`0x20`) — бит
  включения 3D `0x2000` с сохранением остальных битов. На этой карте чтение
  может вернуть `3D=000f GP=2000`. Владелец подтвердил слышимый эффект на
  стабильной аналоговой версии. Аналоговый движок публикует отдельный toggle
  control для приложения `YMF754Control.app`: он включён по умолчанию и меняет
  только AC'97 аналогового выхода, не затрагивая S/PDIF. Это отдельное
  приложение, так как панель «Звук» Snow Leopard не показывает этот control.

При запуске драйвера PCI bus mastering включается до загрузки firmware — это
необходимо для проверенного холодного старта этой карты. При старте PCM DSP
получает подготовленные DMA-базы и IRQ. При обычном закрытии PCM драйвер очищает
MODE, оставляет CONFIG/DSP включёнными,
ожидает завершения текущего банка (до 20 ms), затем отключает PCI bus mastering.
Это позволяет следующему клиенту открыть тот же аналоговый выход повторно без
перепрошивки.
При выгрузке CONFIG/DSP выключаются отдельно — после остановки банка и до
освобождения памяти. Если DSP не становится idle, PCI bus mastering выключается,
движок помечается неготовым и повторный старт отклоняется. При sleep обмен
останавливается; wake повторно загружает firmware, проверяет размеры банков и
восстанавливает кодек. **Sleep/wake тоже требует аппаратной проверки.**
I/O decode включается только если BAR1 и BAR2 содержат разные валидные I/O
адреса в пределах 16-битного порта; исходное состояние восстанавливается при
выгрузке драйвера.

MIDI, дополнительные частоты/разрядности и другие mixer controls пока не
реализованы. Владелец подтвердил работу звука, микрофона, S/PDIF, 3D Wide,
громкости, mute и перезагрузки на текущей сборке. Новый флажок 3D Wide ещё
нужно проверить на целевой системе: включение, выключение и состояние после
повторного открытия приложения.
`YMFPCIDSPState = AnalogPCMReady` само по себе не доказывает наличие звука;
для аппаратной диагностики смотрите IRQ/DMA сообщения ниже.

Исходники ALSA и firmware из предоставленного архива лежат в `Reference/`.
Исходники ALSA сохранены без изменений и не компилируются как macOS-код.
`ds1_dsp.fw` и `ds1e_ctrl.fw` включены как массивы байтов в
`Driver/YMFPCIFirmware.cpp` и в бинарный kext. Остальные firmware-файлы
остаются референсами.
Размеры проверяются, но происхождение и подлинность предоставленных образов
этим не подтверждаются. Лицензия firmware отдельно не была приложена к архиву;
перед публичным распространением бинарных образов необходимо выяснить её условия.

## Открытие и сборка

1. Скопируйте каталог `YMF754-macOS` на Mac с Xcode 4.2 и установленным SDK 10.6.
2. Откройте `YMF754-macOS.xcodeproj`.
3. Выберите схему `YMFPCI` и сборку `Release`.
4. Целевая архитектура проекта — `x86_64`, как в вашей системе.
5. Массивы прошивки находятся в `Driver/YMFPCIFirmware.cpp`; отдельная фаза
   генерации и файлы из `DERIVED_FILE_DIR` для сборки не требуются.
   `Tools/embed_firmware.py` используется для регенерации этого исходника из
   файлов в `Reference/Firmware/`.

Для переключения 3D Wide соберите `ControlApp/YMF754Control.xcodeproj` в Xcode
4.2 и запустите `YMF754Control.app` после загрузки kext. Флажок показывает
прочитанное состояние; если движок ещё не найден, нажмите «Повторить поиск».
Старый `ControlPane/3D_wide.prefPane` для этого не требуется.

Сборка из Terminal на целевом Mac:

```sh
cd YMF754-macOS
xcodebuild -project YMF754-macOS.xcodeproj -target YMFPCI \
  -configuration Debug SDKROOT=macosx10.6 ARCHS=x86_64 build
```

На первом этапе изучите журнал сборки и выполните **проверку без загрузки**:
`kextutil -n -t -v 6 build/Debug/YMFPCI.kext`.
Проверка может потребовать права администратора и правильные owner/permissions
bundle. Не устанавливайте непроверенный kext автоматически в
`/System/Library/Extensions`.

Предыдущий этап (только reset/firmware) пользователь успешно собрал, проверил
`kextutil` и загрузил на Snow Leopard. **Новый вариант PCM ещё не проверен
на этой системе/карте**: здесь нет macOS 10.6.8 или Xcode 4.2.
Загрузка kernel extension изменяет
загружаемый код ядра и может привести к зависанию или невозможности загрузки.
Сначала проверяйте на отдельной установке с резервной копией и способом
восстановления загрузки, а не на основной системе.

## Проверка против настоящего SDK 10.6

SDK можно загрузить и использовать с Clang в Linux, без установленной macOS:

```sh
mkdir -p /tmp/ymfpci-sdk
curl -fL -o /tmp/MacOSX10.6.sdk.tar.xz \
  https://github.com/phracker/MacOSX-SDKs/releases/download/11.3/MacOSX10.6.sdk.tar.xz
tar -xJf /tmp/MacOSX10.6.sdk.tar.xz -C /tmp/ymfpci-sdk
sh YMF754-macOS/Tools/check_sdk.sh /tmp/ymfpci-sdk/MacOSX10.6.sdk /path/to/clang++
```

Вторая опция — путь к Clang с Darwin target; если она опущена, используется
`clang++` из PATH. Изолированные include paths берутся из Kernel.framework SDK
и встроенных заголовков самого компилятора, а не из Linux userspace.
SDK и временные результаты не добавляются в репозиторий.

**Выполнено успешно с Clang 15.0.7:** все шесть `.cpp` драйвера прошли
`-fsyntax-only` и компиляцию `-O2 -c` в Mach-O x86_64 с target
`x86_64-apple-darwin10`, C++98 и `-Wall -Wextra -Werror`.
Это включает IOKit device/engine, DMA, PCM и встроенные firmware-данные.

Эта проверка обнаружила недоступный в kernel SDK 10.6 `OSMemoryBarrier`;
MMIO теперь использует `OSSynchronizeIO`, compiler barrier и некэшируемое
отображение BAR0. Проверка современным Clang не доказывает совместимость
со всеми особенностями LLVM GCC 4.2 и не выполняет линковку, валидацию
зависимостей kext, загрузку в ядро или проверку аппаратуры.

## Платформонезависимые тесты

```sh
sh YMF754-macOS/Tests/run.sh
```

Тесты компилируют платформонезависимую последовательность в режиме C++98:
проверяют reset, все 3104 слова firmware, little-endian преобразование, отсутствие
запуска DSP, неверные размеры, таймауты кодека/DSP, отсутствие устройства и остановку.
Отдельно проверяется ошибка генерации firmware без повреждения предыдущего результата.
PCM-тесты проверяют hardware ABI/выравнивание/границы банков, S16/48k параметры,
раздельные L/R gains, преобразование Float32 (включая NaN/infinity и сравнение
с userspace FPU), кодек и таймауты. Также проверяются состав Xcode target и plist.
Это **не** сборка IOKit-адаптера и не проверка реального PCI/MMIO.

## Проверка нового PCM-варианта на Mac

Проверяйте только на тестовой системе с резервной копией и возможностью
восстановить загрузку. Этот вариант впервые включает PCI DMA и может вызвать
зависание/повреждение памяти при ошибке. Не добавляйте его в автозагрузку.

1. Закройте приложения, использующие аудио. Если предыдущий kext загружен:
   `sudo kextunload -b org.ymfpci.driver.YMFPCI`. Если выгрузка не удалась,
   **не форсируйте**; перезагрузите тестовую систему без автозагрузки драйвера.
2. Соберите обновлённый каталог целиком (Xcode **Clean**, затем Build).
   В target теперь шесть `.cpp`; не заменяйте только один файл старого проекта.
3. Из корня каталога проекта:

```sh
sudo chown -R root:wheel build/Debug/YMFPCI.kext
sudo chmod -R 755 build/Debug/YMFPCI.kext
sudo kextutil -n -t -v 6 build/Debug/YMFPCI.kext
# Только если проверка выше прошла:
sudo kextutil -v 6 build/Debug/YMFPCI.kext
kextstat | grep org.ymfpci.driver.YMFPCI
```

4. Откройте «Настройки системы → Звук → Выход» либо Audio MIDI Setup,
   выберите Yamaha DS-1E / YMF754. Единственный аппаратный формат — 48 kHz / 16 bit.
   Начните с тихого уровня усилителя и используйте аналоговый front/line-out.
5. Запустите звук через обычное приложение, например:
   `afplay /System/Library/Sounds/Glass.aiff`.

Ожидаемые диагностические строки, **если соответствующие события произошли**:

```text
YMFPCI: PCI after safe setup command=0007 I/O BAR1/2=valid; decode enabled
YMFPCI: bank bytes play=... rec=... effect=...; control=... bytes
YMFPCI: AC97 vendor=...; master=0f0f pcm=0000
YMFPCI: analog stereo engine registered: 48000 Hz, signed 16-bit
YMFPCI: PCM started; waiting for hardware IRQ
YMFPCI: first PCM hardware IRQ received
YMFPCI: DMA position advancing (frame ...)
YMFPCI: PCM ring wrap observed; CoreAudio timestamp updated
```

Последние три строки печатаются один раз за запуск, не на каждом прерывании.
`registered` без `PCM started` — клиент не запустил поток; `started` без IRQ —
проверять IRQ/DSP; IRQ без движения позиции — проверять DMA/голоса.
Движение позиции и оборот кольца без слышимого звука — проверять кодек,
аналоговую маршрутизацию и физический выход. При проблеме нужны весь журнал
`YMFPCI:` и вывод `kextutil`; не считайте регистрацию устройства проверкой звука.

После минутного теста пользователь подтвердил чистый непрерывный звук и все
три события IRQ/DMA/wrap. В предыдущей версии закрытие PCM завершилось
`DSP stop timeout`, из-за чего движок запрещал повторный запуск. Это исправлено:
обычное закрытие теперь сначала ждёт `STATUS.busy=0` при включённом DSP, затем
отключает bus mastering и оставляет DSP готовым к следующему клиенту. При
успешном закрытии ожидается `PCM stopped; DSP idle and ready for next client`.
Этот исправленный вариант надо заново собрать на целевом Mac и проверить
повторное открытие/закрытие аудиоприложения.

## После аппаратной проверки

Соберите kext и проверьте аналоговый выход, затем выберите отдельный
`Yamaha YMF754 Digital Output (S/PDIF)` на цифровом приёмнике. После этого
вернитесь к аналоговому выходу и проверьте звук и микрофон. Смотрите журнал на
сообщение `separate S/PDIF PCM engine registered` и строку об остановке
предыдущего выхода при переключении. Raw AC-3 passthrough, SPDIF capture и MIDI
пока не реализованы.
Подробности и границы реализации: [PORTING.md](PORTING.md).
